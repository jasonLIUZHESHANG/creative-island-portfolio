# 创作岛互动作品集

当用户要求安装或使用此技能制作作品集时，直接开始下面的访谈。技能自带可复制的网站模板 `assets/template/`。不要让新人先下载 ZIP，也不要把仓库作者 Jason 的作品当成新用户的内容。

## 对话流程

1. 第一条回复简短介绍成品，然后只问：**你现在是什么状态？1 学生；2 已经工作；3 学生与工作经历都有。** 用户回答后再进入材料收集，不要一次抛出整张表。
2. 依据身份列出四个可调整的模块。工作者默认：工作项目经历、自媒体内容、Vibe Coding 作品、科研与个人研究项目。学生默认：课程与校园项目、实习与实践、创作与内容、研究与个人探索。混合身份可合并两组并让用户选最贴近的四项。若某模块没有内容，允许跳过或换成用户自己的类别。
3. 每次只处理一个模块、一个作品。请用户提供现有文字、链接或图片；追问作品名称、背景、本人角色、具体行动、结果及可公开的证明。团队成果写清归属。没有图片或数据就留空，不编造。整理成可直接放在作品卡里的文字，交给用户核对，再进入下一个作品或模块。
4. 材料收集完后，再问展示姓名、简介、公开链接、网站名称、角色外观偏好。名称可由你给出少量候选供选择；若用户已有名称则采用。默认角色是黑夹克、蓝牛仔裤、白鞋；参考照片仅在用户自愿且有使用权时使用。
5. 展示完整内容清单：四个分类、每件作品的标题、本人贡献、链接与缺失材料。请用户确认或修改，然后开始生成。用户只有少量作品也可以做清楚标注的草稿。
6. 把本技能目录中的 `assets/template/` 复制到用户选定的新项目目录；若用户已有项目，先读其 README 和 `src/portfolio-config.js`，在原项目继续。只编辑副本。把核对后的内容写入 `src/portfolio-config.js` 的 `profile` 与 `portfolioSections`。作品条目格式为 `[标题, 本人角色与贡献, 可选封面路径, 可选详情链接]`。封面放进 `public/covers/`；未获授权的素材不复制。不要保留示例作品作为用户成果。
7. 检查 Node.js 版本需至少 20.19，在项目目录执行 `npm ci`、`npm test`、`npm run build`、`npm run dev -- --port 4174`。打开本地浏览器预览；核对标题、作品、四个场景、分类入口、手机布局及链接，并根据反馈修改。默认首场景是云朵花语。
8. 告知用户新项目路径和预览地址。发布网站是单独的后续步骤，只有用户要求发布时才进行；公开前核对姓名、作品归属和图片授权。

## 网站规则

四个场景是云朵花语、海风小岛、风栖草原、雪线暖屋，分类和浏览进度在场景间共享。点击动物或底部分类看作品；点击地面移动人物，拖动旋转，滚轮缩放。音乐默认关闭。网站需 WebGL 浏览器，不依赖后端、Blender 或付费 API。代码遵循 LICENSE；个人照片和作品另需本人授权。
